# 共鸣：闻声对决 · 玩家旅程

[返回产品设计总览](product-design.md)

日期：2026-10-24。状态：当前产品设计；未交付能力单独标明。

描述玩家从进入、配对、战斗到结束与再战的完整流程。当前实现与设计目标的区别见[总览说明](product-design.md)。

## 1. 进入与选择模式

**已确认上手方向**：朋友可以直接进入双人对战，单人练习自选，不要求先完成练习或教程。规则按当前阶段逐步提示，不在开局介绍全部招式；这是产品设计目标，尚未实现或验收新手引导。现有开局语义与合法行动范围不变。

玩家进入智能体后，需要知道“我可以指挥伙伴战斗”，以及单人练习和双人对战的入口。现有语音中，“开始游戏”开单人局，“开房间”开双人局；不要用同一条无说明的“开始”按钮暗示它一定会加入真人对战。

入口介绍话术：“我是你的战斗伙伴。说开房间和朋友对战，或说开始游戏练习。”该话术尚未加入平台欢迎语。

没有对局时直接说出可识别的招式，当前会自动创建单人局并尝试执行；伙伴需要说明已经开局。双人场景应先明确开房或加入，避免把练习误认为已连接朋友。

## 2. 建房与加入

1. A 说“开房间”，获得四位房间号，伙伴说明等待另一位玩家加入。
2. A 把号码告诉 B；B 对自己的设备说“加入房间1234”（以实际号码替换）。
3. 加入成功后双方属于同一局，先手随机决定，房主不固定先手。现行实现创建房间时即生成初始对局，加入后可行动，没有额外准备步骤。
4. 号码无效、房间不存在或满员时，说明原因，不悄悄改开另一种模式。

当前房主不会收到服务端主动语音通知。有屏设备可看状态更新；无屏房主在对方确认加入后说“战况如何”，获知开局状态和当前阶段。面对面时接受对方口头确认已加入，再由房主主动查询；不以缺少主动通知本身判定流程失败。

## 3. 战斗循环

```text
先手主动选择
  ├─ 蓄力 → 交给另一方主动选择
  └─ 攻击锁定 → 另一方响应 → 统一结算 → 检查胜负
                                              ├─ 结束
                                              └─ 未结束 → 另一方主动选择
双方各完成一次主动行动后进入下一完整回合
```

上图描述通常顺序；防守方能量为零时自动承受，不等待响应输入。每次攻击后的击倒立即结束，不等双方都行动。

伙伴在指令生效、攻击结算和防守反馈这些已有回复节点，以自身视角回应玩家，并在行动交接时请求下一步指挥；表达规则与示意见[伙伴短反应](voice-and-feedback.md#14-伙伴短反应)。这里玩家的主动与响应指选择伙伴的行动，实际出招、承伤与生命值变化属于伙伴；不新增确认问答或等待步骤，本旅程不重复维护表达规则。

面对面时玩家可听见对方伙伴的公开播报，但不能把这种听见当作稳定的系统通知；有遮挡、噪声或不确定时应能查询。已确认接受朋友互相提醒“该你了”或“我已出招”，也接受玩家主动查询，主动查询是无屏场景的必要交互。评估重点是提醒与查询后能否理解局面并流畅互动，不要求系统独立完成全部行动交接，也不要求玩家无依据地猜测阶段。

### 3.1 首次与朋友开打一局

已确认的首次必要提示分布如下；这是玩家需要获得的信息，不是新增一串必经问答。本轮演示采用玩家主动开启的本局引导，不做自动新手识别或跨局记忆；此方案尚待实现，不能宣称已有持续引导开关。

| 节点 | 首次需要理解的事 | 当前流程与设计边界 |
| --- | --- | --- |
| 进入和配对 | 自己指挥伙伴；一人说“开房间”，朋友说“加入房间”加实际四位号码 | “开始游戏”仍为单人练习入口；不增加练习门槛、准备确认或主动欢迎通知 |
| 首次主动 | 现在可以指挥出招；先认识普攻1点能量、强攻2点能量 | 仅减少初次介绍量；大招、蓄力等其他合法动作不被禁用，仍校验资源与阶段 |
| 首次响应 | 攻击还没结算；格挡减2伤、闪避可能成功也可能失败，两者各花1点能量；承受不消耗能量但吃伤害 | 进攻与防守共用能量；能量为零按既有规则自动承受，不等额外响应 |
| 响应结算后 | 实际受伤和剩余资源是什么；未结束时，同一位玩家接着指挥伙伴主动出招 | 不把响应结束误说成轮到另一位玩家；击倒立即终局，不再请求出招 |

不确定当前阶段时可说“战况如何”，需要通用规则时可说“怎么玩”；不要求每次行动前都查询。大招、蓄力、恢复能量与增伤规则通过按需帮助和相关反馈逐步认识，不能将此设计目标写成已支持任意规则问题的精准回答，现有战况查询已回答双方大招剩余次数，输入与反馈边界见[语音输入与反馈](voice-and-feedback.md#12-理解失败与歧义)。

#### 本轮演示的最小引导方式

- 玩家自主选择是否开启引导；未选择时不自动判定为新手。开启后仍直接与朋友开打，不先走单人练习、独立教程或准备确认。
- 选择仅作用于本方本局，采用对局内有限状态：是否启用，以及首次主动、首次响应、首次响应转主动的提示是否已给出。无需用户画像、长期存储、历史局数或理解程度判定。
- 开启后只在上述相关阶段的已有回复中补必要规则，提示过就回到日常简短反馈；查询不重置已提示状态，不因重复查询而重播教程。未到相应阶段不提前连讲规则，也不发起额外播报或等待确认。
- 关闭后保留正常战况、阶段提示和错误恢复，“怎么玩”仍可随时请求一次通用帮助。换局不继承本局引导选择和进度，需要时由玩家重新选择；不新增跨局偏好管理。

当前“怎么玩”只返回一次玩法说明，不开启或关闭持续引导。持续引导开关尚未实现，本文不定义已可执行的新口令，不增加必经选择问答。表达边界见[分阶段上手提示](voice-and-feedback.md#15-分阶段上手提示)。

### 3.2 首次攻防对话示意

下表假设双方已通过后续待实现的入口主动选择本局引导，沿用现有建房、加入、查询和行动路径，**伙伴回复是建议文案，不是当前实现的逐字记录或固定台词**。表中不虚构已可执行的开启口令。假设A随机先手，双方初始能量3，A生命值14、B生命值18，A这次普攻未暴击；真实先手、数值与伤害均以服务端为准。玩家当面交流不会自动变成设备间消息。

| 节点 | 玩家行为 | 伙伴回复示意或现场交流 |
| --- | --- | --- |
| A建房 | A：“开房间。” | “房间1234开好了，把房间号告诉另一位玩家，说‘加入房间1234’就能进来。” |
| B加入 | B：“加入房间1234。” | “我进了房间1234，对面就是另一位玩家。对决开始，对手先手，我18点生命值，对手14点生命值。” |
| 朋友确认加入 | B当面对A说“我进来了” | 这是玩家之间的交流，A的设备不会因此自动播报 |
| A获知开局 | A：“战况如何？” | “第1轮，我14点生命值、3点能量，对手18点生命值、3点能量，我还剩一次大招，对手还剩一次大招。该我出招，听你的。” |
| A主动 | A：“普攻。” | “我出普攻，接招！等对手应对。” |
| B了解应对 | A当面提醒“我出招了”；B：“战况如何？” | “对手普攻，我18点生命值、3点能量。格挡减2伤、闪避赌躲开，都花1点能量；承受不消耗能量。” |
| B响应并转主动 | B：“格挡。” | “我格挡普攻，掉1点生命值，剩17，能量2。现在指挥我出招，用的还是这份能量。” |

B接下来首次进入主动阶段不恢复能量，所以仍为2点能量；不能示意成恢复到4点能量。后续各自主动阶段才按现行规则回2点能量、上限5。A的普攻尚在等待响应时不能宣布命中；B结算时才知道这次伤害。当前A不会同步听到B的结果，可当面交流并在下次行动或查询时获取已有补账；不假设问玩法也必然补账。v2 计划通过等待请求接续反馈，但尚未实现，不能把此示例解释成设备已经能够主动通知。此示意用于看清第一次交接，不规定必须照着这些行动打一遍。

### 3.3 错误输入与继续行动

首次误说不增加“确认后重来”的步骤：伙伴说明未生效原因，并给出当前阶段、当前资源下可执行的说法，玩家直接说下一条合法指令。未知说法或识别失败不扣资源、不推进阶段；不把“没听清”说成战斗受伤。能量不足与阶段错误的措辞示意见[分阶段上手提示](voice-and-feedback.md#15-分阶段上手提示)。

网络请求失败而结果不确定时，应先查询战况核实是否已生效，再决定下一步；不能因为没听到回复就引导玩家重复一个可能已经结算的攻击。首次必要教学与日常简短反馈分开，不能让每局或每次查询重复完整教程；不增加播报轮次或额外等待。不做自动首次识别、跨局记忆、账号或长期偏好管理。

## 4. 胜负与再来一局

任一方生命值归零后立即结束，双方从各自视角得到相反且一致的胜负结论，不再接受战斗行动。当前最后一次结算只直接回复发起请求的设备，另一位无屏玩家需通过后续行动补账或查询获知终局。v2 等待能力交付时，仍须验证双方都能获知同一终局，不能因关闭等待或重复查询而遗漏、重复播报；等待能力本身不改变胜负。

胜负明确时，伙伴可在原有终局回复中自述战果、表达庆祝或失落，与玩家交流，沿用[伙伴短反应](voice-and-feedback.md#14-伙伴短反应)的边界；不要求玩家额外回应，不增加对话轮次或改变下述再战路径。

当前“开始游戏”“再来一局”会新开单人局；在双人房中重开会撤掉旧房。继续和同一朋友对战的现有路径是重新开房、另一位重新加入，不能把它描述为已支持房间内再战。
