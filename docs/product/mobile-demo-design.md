# 共鸣：闻声对决 · 手机模拟硬件演示

[返回产品设计总览](product-design.md)

日期：2026-10-24。状态：已确认的产品关系与演示边界；本文件不代表已实现或验收。

## 1. 定位与范围

手机模拟仅在硬件不足时补充2026-10-26现场演示，最终产品不是手机端。两名朋友面对面，各用一部手机，通过语音指挥伙伴，无需触控出招；这不延伸定义系统级授权或启动交互。画面先以伙伴表情为主要表现，结合硬件概念外观，防御时仅增加必要的局部小手持盾姿势，不展开复杂身体或全身动作；视觉优先级与长期硬件小屏一致，以伙伴形象和表情为主，其他状态信息为辅助，营造伙伴感，不做成仪表盘。

手机画面以伙伴为主角，硬件外观作为承载伙伴的背景或边框；不将设备与角色并列为各占独立区域的两个展示主体。此原则限制的是角色与硬件的主次关系，不限制同一设备的正、背双视图。

本次真实硬件演示仍沿用无屏双设备。长期硬件的小屏方向不等于10月26日必须交付小屏设备。

## 2. 伙伴与硬件的关系

伙伴是住在硬件里的独立角色，硬件是承载设备，二者不是同一个角色。玩家交流、指挥和养成的对象是伙伴。

长期产品允许一台硬件承载和养成多个伙伴，不要求每个伙伴单独购买一台硬件。这样可以降低拥有多个伙伴的硬件成本，并支持产品长期发展。这一关系不定义多伙伴切换、单场出战数量或养成机制，也不代表本次演示实现这些能力。

## 3. 硬件与模拟表达边界

真实有屏伙伴设备在对战时，正面小屏朝向对手，背面朝向主人；背面只有外壳与指示灯，没有屏幕。主人从背面指挥伙伴。这是有屏硬件的空间关系，不改变本次无屏双设备演示路径。

手机采用竖屏布局，上方展示较大的正面视图，下方展示较小的背面视图，分别标注“对手看到的正面”“主人看到的背面”。两者同时展示本方同一台硬件。正面区域优先呈现伙伴形象与表情；背面只展示外壳与指示灯，不增加屏幕或重复战况面板。

每部手机同时呈现本方同一设备的两个观察视图：一个是对手看到的正面，一个是本方主人看到的背面。双视图展示同一伙伴、同一设备的同步状态，不是双方玩家各自伙伴并列，不是两个独立设备或两份独立对局状态。它用于演示观察角度，不暗示实际硬件有双面屏。

语音是主人获得指令是否被接收、是否需要重说、行动战果、轮转与胜负等既有必要信息的主通道，不能被正面表情、角色动作或背面灯效替代。主人不应被要求观看朝向对手的正面屏幕；朋友互相提醒与主动查询仍可用。沿用现有短语音规范，不增加重复播报或每阶段的额外确认；页面 `push` 只在对手动作或长时间空闲时补一句，不作为每阶段确认。手机双视图能看见正面，不构成删减真实硬件使用所需语音反馈的理由。

| 内容 | 当前已确定的边界 |
| --- | --- |
| 长期硬件方向 | 包括外部指示灯与简单小屏幕；小屏主要显示伙伴形象与表情，其他状态信息为辅助；不定义具体硬件造型或灯效映射 |
| 实体硬件震动 | 仅为可考虑能力，不因手机中的模拟效果而成为已确认、已交付或本次演示承诺 |
| 手机模拟震动 | 通过画面中硬件外观的短暂晃动表达，不要求调用手机实际震动；晃动对象是硬件外观，不默认带动整个手机界面或战况文字；不定义触发事件、强度、时长或动效细节 |
| 手机伙伴表现 | 当前版本以表情为主，防御增加最小的局部小手持盾姿势，不展开复杂身体或全身动作；此前允许模拟角色动作的边界不等于本版必须展示动作 |
| 战斗与交互 | 沿用现有服务裁决、伙伴第一人称交流与短反馈，不增加问答轮次或每阶段确认；主动推送只覆盖对手动作、该行动却空闲与等待提醒，终局不重复播报 |

沙箱手机页面已接入 `/events` 的 `push` 事件：对手进房、对手出招、轮到自己却一段时间没开口、等对手或等客人过久时，伙伴主动补一句；页面正在朗读时排队，玩家说话、打字或页面隐藏时不抢麦，麦克风只是开着待机时仍会朗读并短暂暂停收音。该能力仍需真机验收；手机侧 ASR/TTS 由手机客户端实现，不在本文件范围内。

竖屏、上正下背，正面以伙伴为主；生命值以爱心图标与绿色辅助条常驻，不专门显示数值；能量以五个闪电常驻，拥有为黄色实心、耗尽为灰色空心，不使用能量条或数字主显示。设备屏内不显示这些资源名称。大招在正面小屏右上角使用与闪电能量不同的原创圆核气焰徽记：未就绪为空心核心与断弧，可释放为实心核心、完整弧和圆钝向上气焰，本局已用时气焰消失并以核心斜划表示耗尽，不能只靠颜色区分，也不在屏内堆叠状态文字。大招可释放时的眉眼复用接受指令状态，不复制嘴型或接受状态的边框慢闪。仅当前确实可释放大招时，小屏使用橙色深绿的统一蓄势背景，上升气焰从表情后方下缘形成连续宽底，以少量圆钝、长短不一且不对称的焰头向上流动，替代两侧括号弧，局限在正面小屏内，不遮挡表情、资源或右上角标；已用、能量不足、非主动或待应对、连接未知及终局均不显示可释放气场。可释放时气焰通过较快流动与错峰伸缩表现蓄势，背景以2.6秒周期低频柔和明暗辅助；具体流动参数仍为原型假设；离开可释放条件立即清除循环，减少动态效果时保留静态能量纹理，具体气场形态与节奏仍为原型视觉假设。依据现行规则：对局进行中、轮到本方主动且无待应对攻击、能量至少4点、本局大招仍有次数，才可释放；本局仅一次。应对、等待、能量未足、已用与对局结束不显示可释放，连接结果不确定时先核实。两处视角标注用于手机演示，不是实体背面的文字；背面不增加数值、文字或屏幕。本文件不定义具体指示灯编码、外壳细节或硬件造型，硬件晃动的触发规则与动效参数保持未定义。

## 5. 设计原型

[HTML 讨论原型](prototypes/mobile-companion.html)用于观察正背双视图、伙伴形象和状态反馈。它是无后端的独立静态设计资产，不代表真实语音识别、双机对战或状态控制已实现。原型以爱心与生命条、五闪电能量、右上角圆核气焰徽记呈现辅助状态，屏内不堆叠资源状态文字。受击、失败通过明显不同的表情，配合正面屏幕背景和同一设备两侧指示灯进行视觉探索；防御仅增加清晰持握盾牌的局部小手，不扩展复杂全身角色。待机采用放松表情，模拟倾听采用显著专注的眉眼与嘴部姿态，并辅以屏幕边缘、背景及两侧指示灯，静态下也可区分。各状态沿用同一角色的眼睛、嘴型、配色与漫画线条；表情在正面小屏居中且占更大空间，生命条适度加厚、与五个闪电能量并排为一行；盾牌与气场不遮挡资源，右上角为大招徽记。能量不驱动表情变体，只改变五闪电资源和大招可用判定；资源演示复用同一待机场景，不增加零能量或满能量的重复视觉状态，也不执行行动。所有表情及闪避左右虚影共用单色整体眼形，不加独立眼珠或异色描边；睁眼采用纯实心单色眼形，不保留内孔、高光或独立瞳孔，闭眼与欢呼沿用同色轮廓。固定眼睛中心、统一眼部边界和嘴部锚点，只改变眉形、眼睑、嘴轮廓及辅助符号；闭眼或欢呼仍使用同一眼部区域，举盾遮挡不移动五官。需重说增加问号表达未听懂，与断网符号区分。防御把盾举到脸前，允许遮挡眼睛，以简化握手明确持盾区别于倾听、大招气场和受击；举盾不代表必定免伤，已结算格挡的实际承伤仍由必要语音说明。原型中的虚线盾仅作未裁决意图的视觉预演，不代表真实服务存在独立中间状态，也不新增确认播报。已接受指令状态可用屏幕边框及两侧灯同步低频柔和变化，减少动态时用稳定强调；不提前表现实际命中。断网保留正常设备与屏幕配色，用无网络图标替代表情，生命条与能量闪电标为未核实视觉，不冒充当前资源或可用大招。闪避单独演示未裁决意图与实际成功/失败：成功用同一伙伴的三张同尺寸虚影表示闪避：两侧更淡且固定，中间整张脸快速左右往返；全部复用同一脸部结构、固定五官比例，不缩放，允许局部重叠，不把五官单独错位，也不表示多位伙伴，外壳不使用受击式晃动；失败仍按实际承伤反馈，不预先保证躲开。减少动态时保留静态三影，不增加无关攻击物。胜利用夸张喜悦的眉眼和张嘴欢呼，眼睛与嘴巴均为单色；嘴巴仅保留清楚轮廓，不叠加舌头或牙齿细节，腮红保留，仍沿用同一角色。受击短促、失败持续，减少动态效果时仍可通过静态表情辨识。倾听状态不表示接入真实麦克风，也不增加倾听播报。美术以原创卡通漫画表情、清晰轮廓、适度赛璐璐色块与冲击线进行探索，不复刻具体既有角色或品牌标识。具体造型、灯效映射、颜色、时长与晃动细节在原型中标为讨论假设，不作为最终硬件规范或已实现能力。
