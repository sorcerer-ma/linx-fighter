# 共鸣：闻声对决 · 异常与退出

[返回产品设计总览](product-design.md)

日期：2026-10-24。状态：当前产品设计；未交付能力单独标明。

明确换房、掉线、等待、认输和退出的处理边界。当前实现与设计目标的区别见[总览说明](product-design.md)。

| 情况 | 当前行为 | 体验约束 |
| --- | --- | --- |
| 编号不合法、找不到编号、编号已被别人接受 | 提示失败并说明原因（“编号要四位数字，再说一遍试试”“没找到编号1234的挑战，确认四位数编号再试一次”“编号1234已经被接受了，说「发起挑战」自己开一局，或者换一个编号”），原房间不变；明确加入意图缺编号时提示四位编号，不能交给模型改为创建 | 接受失败不破坏原局 |
| 主动换房（接受另一个编号） | 先验证目标房，再加入并撤旧房与旧局，清除双方补账 | 换房会结束旧局，不是无副作用查询 |
| 对手换房或重开 | 原房间被撤，旧对局不再继续；无新对局时再说招式会开单人局 | 对手进房有页面 `push` 提醒；换房或重开仍无独立主动通知，单人AI不能被描述成原真人对手 |
| 一直不行动 | 无严格响应倒计时或超时判负，长期空闲后过期 | 不临时增加回合硬截止 |
| 页面关闭、设备掉线、请求失败 | 尚无完整掉线判负与暂停恢复流程，内存局面受过期和服务重启影响 | 不据此自动宣布另一方获胜 |
| 玩家说“退出挑战”或“退出房间” | 等待房间可撤销；已结束房间可清理。重复退出如实说明不在房间，不清空单人局 | 仅清理该房间及其成员索引、旧等待和补账，不影响其他房间，不生成新胜负 |
| 已开战退出或认输 | 退出当前明确拒绝并保留双方局面；认输尚无独立流程，开战后退出的取消／判负规则待确认 | 不把退出请求、关闭页面或掉线直接当作认输 |


不能把“设备身份在多轮对话间稳定”解释成已经具备断线恢复、重启恢复或掉线判负能力。请求失败时先查战况确认，不应引导玩家无条件重复一个可能已生效的攻击。明确拒绝与执行结果未知必须区分；表达或播放失败也不能重新执行行动。

本分支已实现 v2 的有界等待、取消和旧局隔离，平台／真机仍待验收。等待结束、超时或取消都不等于回合判负或认输；仍须在真实场景验证对手离开、换局及迟到结果不会让玩家等错对局或听到旧战果，不把协议等待时限当成新增战斗倒计时。

### 手机伙伴主动提醒

手机页面可在对手出招、接受挑战、大招资源就绪和真实等待／空闲时主动提醒。提醒仍依据当前权威战况，由伙伴演绎，不直接复读服务端原文，也不替玩家出招。玩家说话、输入、当前反馈或页面隐藏时不抢麦；取消、换局与过期提醒不补播。与等待反馈只交付一次，不能为增强伙伴感增加重复战报。平台硬件能否同样主动开口仍须单独验收。
