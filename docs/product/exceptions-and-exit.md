# 共鸣：闻声对决 · 异常与退出

[返回产品设计总览](product-design.md)

日期：2026-10-24。状态：当前产品设计；未交付能力单独标明。

明确换房、掉线、等待、认输和退出的处理边界。当前实现与设计目标的区别见[总览说明](product-design.md)。

| 情况 | 当前行为 | 体验约束 |
| --- | --- | --- |
| 编号不合法、找不到编号、编号已被别人接受 | 提示失败并说明原因（“编号要四位数字，再说一遍试试”“没找到编号1234的挑战，确认四位数编号再试一次”“编号1234已经被接受了，说「发起挑战」自己开一局，或者换一个编号”），原房间不变 | 接受失败不破坏原局 |
| 主动换房（接受另一个编号） | 先验证目标房，再加入并撤旧房与旧局，清除双方补账 | 换房会结束旧局，不是无副作用查询 |
| 对手换房或重开 | 原房间被撤，旧对局不再继续；无新对局时再说招式会开单人局 | 对手进房有页面 `push` 提醒；换房或重开仍无独立主动通知，单人AI不能被描述成原真人对手 |
| 一直不行动 | 无严格响应倒计时或超时判负，长期空闲后过期 | 不临时增加回合硬截止 |
| 页面关闭、设备掉线、请求失败 | 尚无完整掉线判负与暂停恢复流程，内存局面受过期和服务重启影响 | 不据此自动宣布另一方获胜 |
| 玩家说认输或退房 | 尚无独立、完整的产品流程 | 退出、中断与正常击倒分别记录，不把关闭页面当作认输 |


不能把“设备身份在多轮对话间稳定”解释成已经具备断线恢复、重启恢复或掉线判负能力。请求失败时先查战况确认，不应引导玩家无条件重复一个可能已生效的攻击。明确拒绝与执行结果未知必须区分；表达或播放失败也不能重新执行行动。

v2 的等待消费与去重尚未实现；文本模式的 `wait_event` 已实现，仍待真机验收。页面 `/events` 的 `push` 是另一条有屏提醒路径，不是 `wait_event`，不能用来宣称等待返回或平台主动通知已实现。等待结束、超时或取消都不等于回合判负或认输；仍须验证对手离开、换局及迟到结果不会让玩家等错对局或听到旧战果，不把协议等待时限当成新增战斗倒计时。
