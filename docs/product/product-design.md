# 共鸣：闻声对决 · 产品设计总览

日期：2026-10-24。状态：供实现对齐与首次试玩评审的产品初稿。

本文定义玩家体验、产品范围和验收方式，不重复维护战斗数值。当前实现基线为已合并 PR #2 的 `2789c96`；“现有能力”指仓库实现和已有验证记录，不代表灵犀真机已经验收。“建议设计”与“待决策”不作为已确认需求。

已确认方向（2026-10-24）：本轮优先服务于 2026-10-26 现场演示，准备无屏双硬件与手机模拟设备两套演示方案。核心体验是线下面对面指挥伙伴、与朋友热闹对战；明牌资源策略与心理博弈服务于这一体验，不以增加策略复杂度为目标。无屏场景接受玩家互相提醒与主动查询，不要求系统独立完成全部行动交接。手机演示已确认两人各用一部手机、语音指挥，无需触控出招；它仅在硬件不足时作为演示补充，最终产品不是手机端。展示方向为突出伙伴形象、动作及真实硬件的样子；具体硬件与展示细节后续讨论，不代表已完成交付。

## 1. 产品设计构成

游戏玩法、玩家旅程、语音与信息反馈共同构成核心体验：玩法定义玩家能做哪些选择及其后果，玩家旅程串联从进入到结束的完整流程，语音与信息反馈确保玩家听得懂战况、知道何时行动，并感受到自己在指挥伙伴。定位与范围明确产品目标，异常与退出保障流程完整，验收与试玩检验体验是否达成。

## 2. 下一轮设计决策

| 决策 | 当前建议 | 作出决定所需的证据 |
| --- | --- | --- |
| 手机模拟设备的演示边界与后续细化 | 已确认双手机、语音指挥、无需触控出招，仅补充硬件不足时的演示；突出伙伴形象、动作和真实硬件样子 | 硬件产品及展示细节留待后续讨论，并体现在手机演示中；不预设造型、布局或系统级授权与启动交互 |
| 无屏行动交接的理解与流畅性 | 玩家互相提醒与主动查询已获接受；更自然的提示仍属候选改进 | 查询和提醒能否解答当前阶段、是否打断面对面互动；分别记录玩家提醒和主持人介入 |
| 针对状态的简短回答 | 优先补齐大招次数等具体查询 | 现有查询信息缺口及玩家常问的问题 |
| 双方准备确认 | 暂不改现有加入即开打路径 | 玩家是否经常尚未准备好就开始，是否容易误入 |
| 房间内再来一局 | 候选改进，需要双方同意 | 试玩中的再战意愿、重新配对成本和误开单人局次数 |
| 退出、认输与掉线 | 分开定义结果，暂不引入自动判负 | 真实中断类型、持续时间、玩家能否理解恢复或结束 |
| 伙伴性格、台词与演出 | 先保证阶段和结果清楚，再加短表现 | 玩家对伙伴感的评价、台词是否遮挡操作 |

除已明确标注的确认项外，上表均为候选改进或待决策项，尚未形成新增开发承诺。基于已确认定位，建议在已确认的演示边界内验证两套方案能否流畅完成对局，再处理妨碍伙伴感、现场互动和理解战况的问题；复杂博弈、隐藏信息与数值重构不作为当前优先方向。具体交互与实现仍需讨论，不由本轮文档更新定案。
