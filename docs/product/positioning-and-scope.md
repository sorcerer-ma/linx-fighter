## 1. 产品定位

共鸣：闻声对决是面向支持灵犀的硬件设备的语音对战游戏。伙伴是住在硬件里的独立角色，硬件是伙伴的承载设备。玩家与自己的伙伴交流，指挥它与朋友的伙伴战斗，击倒对手取得胜利。

长期产品关系是一台硬件能够承载和养成多个伙伴，不要求每个伙伴单独购买一台硬件，以降低拥有多个伙伴的硬件成本并支持长期发展。这一关系不规定切换方式、单场出战数量或养成机制，也不代表10月26日交付多伙伴能力。

硬件的长期设计方向包括外部指示灯与简单小屏幕；震动仅为可考虑能力，不属于已确认或已交付能力。小屏以伙伴形象与表情为主，其他状态信息为辅助，目标是伙伴感而非仪表盘；手机模拟遵循同样的视觉优先级。手机演示的生命辅助条、能量点与大招提示按[手机模拟硬件演示](mobile-demo-design.md)呈现；该原则不定义其他状态的具体布局，也不定义灯效映射与震动触发。

玩家负责进攻、防守与资源取舍，伙伴负责接收指令、回应玩家和演绎战况。服务端维护唯一对局与裁决结果，伙伴不能凭角色性格擅自替玩家出招、修改伤害或编造胜负。

核心体验（已确认）：**“我指挥自己的伙伴，和朋友面对面打一场热闹的战斗。”**

面对面社交乐趣与伙伴感优先；明牌资源策略和心理博弈用于支持热闹对战，不以复杂计算、深度博弈或竞技性作为本轮优化目标。

对外产品围绕独立伙伴与承载硬件展开；网页和手机沙箱是设备替身，用于开发、试玩和无硬件演示，沿用同一套游戏服务。单人 AI 对手提供练习与独自体验的入口。

本轮优先服务于 2026-10-26 现场演示，已确认准备两套方案：本次真实硬件演示沿用无屏双设备，不要求为10月26日增加小屏；手机模拟方案由两人各用一部手机、语音指挥，无需触控出招。手机仅在硬件不足时作为演示补充，最终产品不是手机端。展示突出伙伴形象、动作及真实硬件的样子；无需触控出招仅定义战斗输入，不延伸定义系统级授权或启动交互。现有沙箱具备手机访问能力，不等于新版手机演示已经设计或验收完成。

手机演示可视化边界见[手机模拟硬件演示](mobile-demo-design.md)。

## 2. 首轮玩家与场景

| 场景 | 玩家想完成的事 | 产品需要支持的体验 |
| --- | --- | --- |
| 两位朋友面对面 | 各自指挥一台设备，打一场并分出胜负 | 明确配对、谁先手、当前谁出招或应对、结果是什么 |
| 初次接触玩法 | 不看长说明也能开始尝试 | 提供短指令和阶段提示，错误输入可重说 |
| 一个人练习 | 熟悉进攻、防守和能量使用 | 用单人 AI 局走通战斗，明确对手为 AI |
| 演示或开发 | 不依赖实体设备复现一整局 | 沙箱多窗口或脚本走真实输入和结算链路 |

首轮以同一空间内的双人对战为主要验收场景；硬件方案明确为无屏双设备，手机模拟方案为两人各用一部手机、语音指挥，不预设玩家年龄或既有游戏经验。无屏对战接受朋友互相提醒“该你了”与玩家主动查询，主动查询是必要的交互方式，不因使用提醒或查询本身判定体验失败。远程使用体验、陌生人匹配和长期留存暂不作为本轮验证目标。

## 3. 体验目标与判断依据

| 目标 | 可观察的结果 | 验证边界 |
| --- | --- | --- |
| 有指挥伙伴、与朋友热闹对战的感觉 | 玩家能将自己的话与伙伴行动、结果对应起来，并与朋友保持现场互动 | 真人访谈和观察，不能用模型调用成功率代替 |
| 知道何时该说什么 | 能借助伙伴反馈、朋友提醒或主动查询区分主动、响应、等对手和结束 | 提醒与查询本身不算失败；观察是否仍困惑或卡住 |
| 能作资源决策 | 理解进攻和响应共享能量，知道大招有次数成本 | 询问玩家为何蓄力、格挡、闪避或主动承受 |
| 战斗结果可信 | 双方看到同一结果，语音查询不触发攻击 | 服务回归与双端对照，再做真机验证 |
| 节奏适合短时对战 | 多数对局在 3～5 个完整回合结束，播报不遮挡下一次选择 | 轮数与实际时长分别记录，不用轮数替代真实耗时 |

完整回合是双方各完成一次主动行动，不是一次说话。没有强制五轮结束规则。既有 256,000 局模拟中 87.53% 在 3～5 轮结束，但启发式策略池不能证明真人公平性；局部先后手差异与后期闪避集中仍需观察，详见[早期测试验证](../archive/v0.2/test-validation.md)。

## 4. 范围与现状

| 能力 | 当前状态 | 本轮产品设计处理 |
| --- | --- | --- |
| 单人 AI 对战 | 已实现；默认开局进入单人局 | 作为练习入口，和真人联机明确区分 |
| 双人开房、凭四位房间号加入 | 已实现；加入后即可行动 | 沿用，不额外插入双方准备确认步骤 |
| 七种行动、查询、玩法说明 | 已实现 | 指令按阶段呈现，查询与否定不能变成行动 |
| 随机先手、共享能量、唯一大招 | 已实现 | 按现行机制解释，不在本文另定数值 |
| 两位玩家的状态与胜负视角 | 已实现 | 双端战况与胜负必须一致；伙伴以“我”自述，“你”指指挥它的玩家，界面须明确本方与对手 |
| 无屏设备补账播报 | 已实现；v2 等待反馈尚未实现 | 接受当前延后反馈，验证双方获知结果与理解成本；不能把协议设计当作主动通知能力 |
| 有屏状态流与沙箱 | 已实现 | 状态画面辅助理解，所有行动仍经过统一服务 |
| 灵犀真机体验 | 尚未完成验收 | 按无屏双设备方案演示，记录唤醒、ASR、TTS、同室串音和提示词稳定性 |
| 手机模拟设备演示 | 已确认双手机、语音指挥、无需触控出招；尚未验收 | 仅作硬件不足时的演示补充，呈现伙伴形象、动作与真实硬件样子；现有沙箱不等于已完成演示方案 |
| 双方准备、房间内再战 | 未实现 | 不作为现有流程提供 |
| 断线提示、暂停恢复、响应超时判负 | 未实现；目前依赖空闲过期清理 | 保留现有过期行为，不以掉线自动判负 |
| 认输、主动退房的完整流程 | 尚无独立产品流程 | 不能把关闭页面等同于认输 |

本轮不增加排位、账号、自动匹配、多伙伴养成或切换、装备、商店、多人混战、观战或回放；也不改变当前单实例服务的工程边界。长期一台硬件承载多个伙伴的关系不改变这一演示范围。
