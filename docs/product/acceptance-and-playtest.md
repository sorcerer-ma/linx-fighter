## 1. 验收清单

下表是产品验收任务，不是测试通过声明。服务回归、沙箱演练与灵犀真机须分别记录结果，未执行项写“未验证”。

已确认本轮优先服务于 2026-10-26 现场演示，分别准备无屏双硬件与手机模拟设备两套方案。手机模拟方案已确认两人各用一部手机、语音指挥、无需触控出招，仅在硬件不足时作为演示补充，最终产品不是手机端；展示方向为伙伴形象、动作及真实硬件样子。现有沙箱记录不等于新版手机演示验收通过。角色是住在硬件里的独立伙伴；手机可呈现实体硬件做不到的角色动作，需明确其为模拟可视化，不将其作为实体设备机械动作能力的验收承诺。长期指示灯与小屏方向、一台硬件承载多个伙伴的关系，不构成本次演示的小屏、多伙伴养成或切换交付要求。边界见[手机模拟硬件演示](mobile-demo-design.md)。

| 编号 | 验收场景 | 通过标准 | 验证层 |
| --- | --- | --- | --- |
| P01 | 开房、加入和随机先手 | 两人进入同一局，谁先手与初始状态一致，等待期间不能攻击 | 服务、沙箱、真机 |
| P02 | 一次攻击、响应与行动交接 | 按阶段执行，双方最终状态一致，玩家知道接下来该谁说话 | 服务、双人试玩 |
| P03 | 七种行动及资源边界 | 遵循机制文档；零能量自动承受，非法输入不花资源 | 服务回归 |
| P04 | 查询、否定和歧义 | 不出招；查询应回答所问信息，重说提示可理解 | 服务、真机 |
| P05 | 首次不恢复能量、逐轮增伤、立即击倒 | 与现行规则一致，结束后不再执行战斗行动 | 服务回归 |
| P06 | 无屏双人完整一局 | 不看网页完成加入、战斗、查询和获知胜负；允许朋友互相提醒和主动查询，分别记录玩家提醒与主持人介入及其原因 | 双硬件试玩 |
| P07 | 双人终局视角 | 一方赢、另一方输，最后行动方与等待方都能获知结果 | 服务、两种载体 |
| P08 | 换房成功与失败 | 成功后旧局停止；失败不破坏原局，双方不会永久等待已离开的成员 | 服务、沙箱 |
| P09 | 异步返回、重复与迟到输入 | 无旧局覆盖新局，无重复扣资源；分别验证，不用串行测试代替 | 服务专项 |
| P10 | 同室语音与长播报 | 识别自己的玩家输入，区分技术失败和战斗失败；记录串音、遮挡、重说 | 真机 |
| P11 | 战后继续与离开 | 说明当前重新开房路径，不把“再来一局”误导为继续原双人房 | 双人试玩 |
| P12 | 首次直接双人上手（设计目标，未验收） | 不强制单人练习；本局主动开启引导，阶段提示保留其他合法动作，首次响应后能继续主动；关闭后保留日常反馈与一次性帮助，不因查询重播；错误恢复不扣资源，结果不确定先核实 | 服务边界、双人首次试玩 |
| P13 | 事实驱动伙伴表达（v2 本分支实现，平台真机待验收） | 不朗读 JSON；表达保留已确认战果、必要数字、归属、胜负与下一步；失败有确定性退路，不重做游戏；静默无多余发言 | 服务、沙箱、平台真机 |
| P14 | 等待与最终播报（v2 本分支实现，平台真机待验收） | 房间号先实际播完；双方能获知战果和终局；超时、取消、换局及查询不导致重复播报或听到旧结果，不改战斗规则 | 双人交错测试、沙箱、平台真机 |

手机正背双视图应呈现本方同一设备、同一伙伴的同步状态，不将其当成两名玩家或双面屏硬件。正面小屏朝向对手、背面仅有外壳与指示灯的使用关系下，主人应能以语音为主通道获取既有必要反馈，并可主动查询，不要求观看正面屏幕。表情动作与灯效不替代必要语音；手机双视图可见正面不能作为删减语音的理由，也不新增重复播报或阶段确认。此为设计验收口径，不是已通过声明。

## 2. 首轮试玩与记录

单人练习由玩家自选，不作为双人试玩前置；将直接双人首次体验与练习后体验分开观察。记录实际先后手，不承诺随机先手自然形成均衡样本；公平性需要可控环境下的专项验证，不能用少量体验试玩证明。

v2 验收还需区分协议事实、最终话术、实际播放与回退原因，并观察必要信息与伙伴感是否同时成立；字段完整不等于说得正确，调用成功不等于已经播放。协议迁移依赖见 [实施说明](../engineering/mcp-v2-migration.md)，当前历史对局记录不证明这些目标通过。

每局记录：载体、单人或双人、双方经验、是否自选单人练习、是否主动开启本局引导、先手、结束轮数、总时长、有效战术输入数、重说次数、状态查询次数、阶段误判、玩家互相提醒、主持人介入及其原因、补账长度、大招时机与落空后的反应，以及异常结束原因。已有日志能辅助核对，但这些统计尚未全部实现，不宣称已自动采集。

分别记录和统计：

- 从加入成功到胜负明确的时长，和整局进入流程的时长。
- 每局重说与查询次数；将“没听清”“指令歧义”“规则不合法”分别记录。主动查询是已接受的无屏交互，不以次数非零直接判定失败，应结合是否解决疑问和是否打断互动判断。
- 无主持人介入完成对局的局数，以及提醒或查询后仍不知道该谁行动的次数；朋友之间的自然提醒与主持人指导分开记录，不将前者直接计为体验缺陷。
- 3～5 轮结束比例与按先后手分组的结果，只作为本轮样本观察。

首次上手另外观察：能否区分“开房间”和“开始游戏”，能否理解响应后由自己继续主动、攻防共用能量；记录已解释仍困惑的节点及是否重复教学。演示引导采用本局主动开启，不做自动首次识别或跨局记忆；开关入口与阶段标记尚待实现，需核对换局不继承、帮助不切换引导，试玩记录不宣称这些已实现；不在此新增完成时长或提醒次数阈值。

试玩后优先询问玩家：是否觉得在指挥自己的伙伴、与朋友对战是否热闹顺畅、什么情况打断了现场互动；再询问是否理解能量与后手生命补偿，为什么选择防守或承受，是否知道大招只可用一次，以及是否愿意立刻再玩一局。优先记录结构化事件、耗时和观察笔记；如需录音，另行确定采集方式。
