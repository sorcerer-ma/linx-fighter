# 玩法机制（待补）与接入点

> 本文是框架阶段的玩法施工图：已实现的部分、还空着的机制、以及每一项该改哪里。
> 标「待定」的是需要产品/数值拍板的决策点，代码里对应位置都留了 `TODO(玩法)`。

## 体验目标

玩家用语音下指令，我方角色与对手按回合出招；招式有明确克制关系与风险收益（攻击可能落空、闪避有代价、回气攒资源），玩家靠**选招策略**而非操作赢得对决。播报要短、有节奏感，适合语音听。

## 已实现（框架）

- 对局创建与回合推进，`Battle` 状态由服务端持有。
- 三种招式的口语识别（含同义说法与 ASR 同音误识别，如「公鸡」→ 攻击），认不出时不消耗回合。
- 气血 / 真气两套基础属性，初始值占位。
- 每回合播报：回合数、双方气血真气。
- 战报（`history`）保留最近 30 回合的指令。

**未实现**：任何数值变化、命中判定、对手行动、胜负判定。

## 属性

| 属性 | 当前值 | 含义 | 状态 |
| --- | --- | --- | --- |
| `hp` / `maxHp` | 100 | 气血，归零判负 | 占位值，待平衡 |
| `qi` / `maxQi` | 100 | 真气，技能消耗与战术资源 | 占位值；是否用于强化招式、是否有上限增长待定 |

候选扩展（待定）：护甲/减伤、连击层数、破防值。

## 招式

| 招式 | 口语别名（部分） | 预期作用 | 待定参数 |
| --- | --- | --- | --- |
| 攻击 `attack` | 打、砍、揍、进攻、出手 | 造成伤害，但可能被对手闪避 | 基础伤害、命中率、真气消耗、暴击 |
| 闪避 `dodge` | 躲、躲开、闪开、防御 | 提高本回合躲避概率，或减少受到的伤害 | 闪避成功率加成、是否有代价（真气消耗/下回合命中下降） |
| 回气 `recover` | 调息、蓄气、聚气 | 回复真气 | 回复量、是否同时小回气血、被攻击时是否更脆弱 |

`miss` 的设计要点（待定）：命中率应该由「攻击方命中 - 防守方闪避」共同决定，而不是写死一个常数；闪避回合如果完全免伤，需要给回气回合设置暴露窗口，否则最优解会退化成「一直闪避攒气」。

## 单回合流程（草案）

1. 玩家出招 → 校验合法性（认不出的招式直接返回，不消耗回合）。
2. 对手按策略选招（随机权重 / 血量与真气驱动的简单 AI）。
3. 双方同时结算：先算命中（miss 判定），再算伤害/回气/闪避收益。
4. 更新气血真气，写入战报。
5. 判定胜负：任一方气血归零 → `victory` / `defeat`，否则 `turn + 1`。
6. 生成播报（含本回合关键事件：命中、miss、闪避成功、回气量）。

先手/结算顺序（待定）：同时结算最简单也最公平；若要实现「回气被打断」这类机制，需要引入速度或意图判定。

## 状态机

```
battle ──气血归零──> victory
   └───────────────> defeat
```

`phase !== 'battle'` 时拒绝出招，只提示「说开始游戏再来一局」（已实现）。

## 接入位置

### `resolveTurn`

现在：

```ts
export function resolveTurn(battle: Battle, action: ActionId, now: number): Battle
```

机制接入后建议保持「纯函数」形态（不改入参、返回新状态），这样回放与单测都容易。需要新增的内容：

- 用 `battle.seed` 派生随机数（推荐 `src/game/rng.ts`：xorshift/mulberry32），保证同一场对局可复现；
- 对手行动、命中、伤害、真气变化；
- 把本回合事件写进 `TurnRecord`（如 `events: ['player_hit', 'enemy_miss']`），播报层据此组织语言。

### 播报

`narrator.ts` 目前按状态拼句子。机制接入后建议改成「事件 → 句子」的映射，再由 `narrateTurn` 组合；避免在结算函数里拼中文，方便以后做多语言或音效。

### 工具层

预计不需要改：招式枚举在 `actions.ts`，加新招式时 `game_action` 的 `action` 参数天然支持；若要做「连招/蓄力」这类需要额外参数的操作，再给 `game_action` 加可选参数。

## 可测性建议

- 随机数走 `seed` + 纯函数，单测可以断言「同 seed 同输入必得同结果」。
- 数值平衡可以写一个模拟脚本（复用 `GameService`），跑几万局统计平均回合数、各招式胜率，避免拍脑袋。
- 已有 `scripts/demo.ts` 可以脱离 MCP 快速看播报效果。
