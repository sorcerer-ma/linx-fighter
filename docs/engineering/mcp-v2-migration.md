# MCP v2 实施与验收

## 状态与范围

PR #14 已合并目标协议，**当前 main 仍运行文本协议，v2 尚未实现**。本文协调迁移，不新增游戏规则、通知机制或运行开关。字段与枚举以 [协议](mcp-protocol.md) 为准；玩法数值仍来自 `src/game/rules.ts`。

当前 main 注册 `game_say`、`game_start`、`game_action`、`game_status`、`game_help`，返回可朗读文本，没有 `wait_event`。当前代码包含 PR #16 的双视图、持续聆听、表达模型、`structuredContent.presentation` 和沙箱提示词模板。这些是文本兼容实现，不是 v2 JSON 接口；迁移须复用既有功能而不退回旧页面。

## 职责与实现边界

玩家原话固定进入一次 `game_say`，服务端理解、校验并执行；Agent 只依据返回事实组织伙伴话术。表达或音频失败不再执行游戏。v2 的 `content[].text` 是一个 JSON 对象，既不是最终话术，也不是 `/state` 的界面快照。

| 模块 | 需适配内容 | 可复用与边界 |
| --- | --- | --- |
| 工具与传输 | `src/mcp/tools.ts` 注册目标两工具，编码 JSON；同步 schema、长度边界与工具说明 | Streamable HTTP、SSE、DELETE 收尾保留；不是把 HTTP 响应全改成同一状态码 |
| 服务事实 | `service.ts`、`state.ts` 从真实结果生成阶段、下一步、资源、合法选择、拒绝与事件 | 复用规则、BattleEvent、PVP 视角；不从播报文本反向猜数字或结果 |
| 表现层 | `narrator.ts` 保留特殊 `text` 与平实 `say`，常规人设由 Agent 表达 | 已锁定攻击是 pending，不是命中；基准伤害不是承诺的最终伤害 |
| 错误 | 业务拒绝用 `ok:false/reason`，服务故障与执行确定性分开 | 确定未执行才可重说；未知先核实，不能用网络错误推断没生效 |
| 静默与归属 | 门禁／回灌按协议返回 `silent`，客户端不生成占位话术 | 身份仍来自请求头和座位，speaker 不决定归属；模型不得编身份 |
| 补账与等待 | `store/echoes.ts`、service 保留可解释的事实；等待、查询与后续行动协调消费 | 不能从已保存的字符串恢复事件；过期、换局、离开需清理，不能重复播终局 |
| MCP 客户端 | `sandbox/platform/mcp.ts` 解析并验证目标 JSON，区分传输错误、业务拒绝和静默 | 不把空内容补成可朗读占位句；不靠猜内容在多种协议间来回 fallback |
| Agent 表达 | 接收事实而非原文改写任务；按必要战果、归属、胜负和下一步检查，失败采用 say | PR #16 的原文数字集合／关键词校验不能原样沿用；有限检查不能证明自然语言完全正确 |
| 页面与脚本 | `platform/client.ts`、页面、CLI、自对弈区分协议事实、最终 reply 与表达状态 | 快照继续画界面，最终话术才显示为伙伴并交 TTS；不再开第二条原文播报通道 |
| ASR/TTS | 识别 final 交文字入口，播放消费最终话术并回报完成／失败／取消 | 不解析游戏 JSON，不裁决，不因播放失败重做 MCP；供应商适配不改变游戏事实 |

## 配置与提示词

`MCP_PROTOCOL=text|json` 是协议提出的过渡建议，当前 loader 尚不支持，不能只往 `.env` 填值就声称切换。是否保留文本模式、默认值、工具清单与退出兼容的时机，应在实现前确认，不在文档中预设多层兼容体系。

平台提示词在控制台手动配置和生效，文档提供参考；沙箱启动加载的提示词文件由后续代码变更提供。沙箱已使用 `config/linx-agent-prompt.md` 启动读取模板；它仍按当前文本和 presentation 链路表达，v2 实施时需更新字段规则，不因模板存在就声称已完成迁移。两侧需同步原话入口、字段解释、静默、异常与等待规则，人格可以不同，不要求共用一份完整人格配置，也不宣称能自动同步平台。

v2 常规表达以事实为输入，`say` 是退路而非改写底稿。`silent` 不调用表达模型或 TTS；`text` 保留规则／问答事实；`unknown` 不鼓励重做。沙箱应能在模型失败或检测到事实矛盾时选择确定性退路，平台是否具有相同程序校验不能凭提示词假定。保留必要事实不等于把资源快照逐项念完；人格不得改写战果或掩盖不确定性。

## 实施前需收敛的协议问题

下列是尚需确认的实现契约，不是已实现能力或新增产品决定。

| 问题 | 已有边界 | 需要明确的最小内容 |
| --- | --- | --- |
| 字段与示例 | silent 可合法不出声；能量缺口由服务端算 | silent 的字段例外与 no_ap 示例已补齐；当前 full-ap 等拒绝原因仍需明确映射 |
| 结果确定性 | failed 不能已执行，unknown 不能要求重做 | 不能仅按是否写库分类；写后已能确认成功、最新快照读取失败、传输无回包分别如何表达 |
| 必要播报与体积 | 两句、60 字是常规目标，单行 JSON 目标为 600 字节 | 多事件全部说到与最多两个数字的优先级；超预算不能截断事实或非法截断 JSON；帮助长文的范围 |
| 事实选择与校验 | 数值、归属、胜负以服务端为准 | 哪些是本轮必须表达，哪些是可查询背景；程序如何检测常见矛盾并选择 say，不用原文数字集合代替事实 |
| 等待消费 | 先完成即时话术，再最多调用一次 wait_event；等待不推进战斗 | 超时／取消后的消费关系、等待方终局、重复请求、换局和对手离开；是否需要事件／局面标识，尚不指定机制 |
| 播放顺序 | 房间号不能被挂起延迟，页面不重复播原文 | 平台挂起前能否真正播完；沙箱请求超时与等待上限配合，不能把长等待塞入旧短请求超时 |
| 回灌 | 服务端不知道平台最后念出的句子 | 旧句式正则覆盖缩窄；时间窗、声纹等仍需真机验证，不能把推断写成可靠屏障 |

## 按目的拆分交付

1. 明确上述契约及迁移配置，更新工具和文档验收口径；未实现部分保持目标状态。
2. 生成服务事实与 say/text，补分支、拒绝、镜像和异常测试；不改战斗数值。
3. 实现 MCP 编码和沙箱解析，验证两工具、长度、版本、silent 与错误语义。
4. 将 Agent 改为事实驱动表达，替换旧原文对照校验，保留单次执行及可观测回退类别。
5. 实现 wait_event 与事实补账消费，验证双人交错、超时、取消、换局与终局，不混入游戏规则变更。
6. 集成最终话术、页面与脚本，更新操作说明后做平台／沙箱验收。ASR/TTS 可独立开发，只对接文字 final 与最终话术／播放事件。

## 验证与切换门槛

- `test/tools.test.ts`、`mcp.e2e.test.ts`、`http.test.ts`：工具清单、原话边界、文本块内 JSON、传输、身份、silent、业务拒绝与服务故障。
- `service.test.ts`、`pvp.test.ts`、`echoes.test.ts`、`crosstalk.test.ts`：不改规则，事实和镜像正确；已结算与待响应不同，重复／迟到请求不重做，等待与补账不丢终局、不重复播报。
- 沙箱／Agent 测试：输入只执行一次，表达失败不重做；不念 JSON；静默不生成伙伴气泡；取消后不播放旧结果；终局表情不被实际收音状态覆盖。沿用已有沙箱与 Agent 测试，并增加 v2 特有断言。
- 配置测试和类型检查通过后，分别做脚本、浏览器与真机验收。协议测试不证明 ASR 准确、情绪音色、平台挂起前播完或同室无串音。
- 原文兜底比例、改写成功与失败类别、延迟分别记录，日志不保存密钥或为诊断恢复无关原话全文。不得用“模型被调用”代替“玩家实际听到了正确的伙伴表达”。

切换必须配对验证服务响应与平台／沙箱提示词；文本模板不能用于 JSON 返回，JSON 模板不能用于旧文本返回。先验证一个接入端，再决定扩大范围；不因文档合并自动改部署、重启或替换运行配置。
