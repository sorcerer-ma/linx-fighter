## 0. 环境

- 手机与电脑在同一内网；沙箱用 `pnpm sandbox` 起，电脑打开 `http://127.0.0.1:8100`。
- 手机要语音必须走 HTTPS：用 `mkcert` 配 `SANDBOX_TLS_CERT` / `SANDBOX_TLS_KEY`，或用 `cloudflared tunnel --url http://localhost:8100`。纯 HTTP 只会出文字输入降级，这是预期行为，不算失败。
- 桌面浏览器再开一个窗口当第二位玩家，方便控制“对手多久出招”。
- 验收期间不要改 `/etc/linx-fighter.env`；它现在有两个设备的 `ALLOWED_SPEAKERS=主人,张朔铭`，改错会直接影响唤醒与说话人。

## 2. `wait_event` 超时续挂

现在服务器上只改了 `wait_event` 的工具描述：超时收尾后，如果玩家没改口，模型可以再调一次续挂，最多连续两次；收尾文案仍是原来的“对手还没出手，出了我马上说。”，平台提示词没有动。

触发方法：

1. 两台设备进同一房间，A 先出招，A 调 `wait_event` 挂起。
2. B 故意 30 秒内不出招，让 A 等到超时。
3. A 不说话，观察模型是否紧接着再调一次 `wait_event`；第二次仍超时应如实说对手还没动，不无限重试。

看日志：

```bash
ssh root@linx-fighter-las \
  "journalctl -u linx-fighter --since '2026-10-25 09:00' --no-pager -o cat" \
  | grep -E '挂起等待对手|等待超时|等待被唤醒|"tool":"wait_event"'
```

判读：

- [ ] 超时那条之后 5 秒内，同一 `sessionKey` 出现新的 `挂起等待对手`，说明模型读到了工具描述并续挂。
- [ ] 连续续挂不超过两次；第二次超时后回到正常对话，没有第三次挂起。
- [ ] 续挂期间玩家说别的话，先按新话处理，不继续挂着。
- [ ] 超时收尾文案仍是“对手还没出手，出了我马上说。”，没有变成“我继续盯着”一类承诺。

如果日志里没有第二次 `wait_event`，先确认平台这一轮是否还允许模型继续调工具；不要为了让它重试去改平台提示词——那份提示词已经 12000 字，继续加会稀释前面的规则。把日志时间点和平台原始返回记下来，再决定是否要改服务端行为。

## 3. ASR 易混词

每个词说 3 次，记录实际转写与是否出招。语音环境用真机，不要用键盘输入代替。

| 预期 | 要说/可能被转写成 |
| --- | --- |
| 闪避 | 闪避、傻逼、傻避、闪币、散避 |
| 格挡 | 格挡、哥挡、隔挡、可党 |
| 承受 | 承受、成受、硬抗、硬航 |
| 普攻 | 普攻、普工、公鸡 |
| 强攻 | 强攻、墙攻、重机 |
| 大招 | 大招、大召、大昭 |
| 蓄力 | 蓄力、续力、蓄利 |

重点检查：

- [ ] 应对阶段说“傻逼/傻避/闪币”能出闪避，不再回“没听清”。
- [ ] 主动阶段说这些词不会误出招、不消耗能量；规则外的脏话仍按规则外处理。
- [ ] 平翘舌（z/zh、c/ch、s/sh）与前后鼻音（an/ang、en/eng、in/ing）的常见误写能命中；新增误写先补 `src/game/actions.ts` 的 `asrErrors` 与测试，不要只改词表不补测试。
- [ ] 长句末尾带招式（如“这波先缓一下，闪避”）仍能出招；句子中间提到招式名但不是在出招时，不应消耗资源。

日志里看 `端侧同音纠错命中` 与 `玩家出招` 两条，能区分是本地同音纠错还是模型路由认出来的。若某个词三次都失败，把转写原文、阶段、期望动作记下来，答辩后再补；不要在验收现场改服务端。
