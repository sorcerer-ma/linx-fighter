## 这是什么

《共鸣：闻声对决》是一款用嘴打的回合制对战游戏。

你和朋友面对面坐着，各对着一台灵矽设备说话：强攻、格挡、闪避、蓄力、开大。住在设备里的共鸣精灵会替你出手，也会把战况讲给你听——掉了多少生命值、攒了多少能量、轮到谁动、下一手该怎么防。

没有手柄，没有技能栏，也没有「匹配陌生人」的房间。你唯一的操作，就是开口。

> **共鸣**，是玩家与精灵之间彼此信任、互相回应的那点默契；**闻声**，是这一整场战斗只靠声音进行。

游戏跑在一套服务里，硬件、网页和手机都能接进来：有屏就看界面，没屏就听播报。

## 项目亮点

### 轻社交：把声音还给一桌人

语音游戏多数时候是孤独的——一个人对着一台设备，说一句，听一句。我们把这条声音放回桌上：两台设备、四位编号，朋友坐在对面，围观的人可以起哄，可以替他琢磨下一手，也可以在他喊错招式的时候笑出声。

一局对战于是不再是一次人机问答，而是一场有人看的表演。孩子赢下的第一场，往往就发生在同学面前；同桌的那几个人，比任何广告都更容易变成下一个玩家。这是低龄产品最稀缺、也最便宜的增长方式。

### 平衡与长尾：七个词上手，一局一个样

七个动作、一种资源，规则薄到一句话就能说完，深度却藏在两次博弈里：出手的人不知道对面是挡、是闪，还是硬吃；防守的人看得见来招，仍要在挡、闪与攒能量之间算账。

第三轮起伤害逐轮加成，逼着人回答同一个问题——现在打，还是攒着打。胜负不交给抽卡，也不交给数值堆叠；哪怕能量见底，也能靠读招、蓄力和分配翻回来。上手五分钟，能反复下一年的桌子。

### 语音原教旨：喊出来，招式才有重量

我们没有把语音当成「给按钮换一种输入方式」。语言本身是带能量的：能量攒满、确认发动的那一刻，你把「共鸣冲击」喊出来，伙伴应声而动。那一刻的痛快，点一下屏幕给不了。

也不必背口令。说「给他点颜色看看」也算强攻，说「先稳住」也算格挡——听懂人话，而不是等你说出某个关键词，才是语音交互真正的门槛。

### 突破硬件：先画出终局，再谈商业化

灵矽设备没有摄像头，屏幕很小，它起初只被当作一个会说话的终端。我们没有绕开这些限制，而是把它们当成设计条件：声音是唯一入口，屏幕只在有余力时补看一眼。

产品最终形态就是从这些条件里长出来的：设备是精灵的召唤器，一台设备可以住下不止一只精灵，每一只都有自己的名字、脾气与成长——玩家认领的是角色，不是功能。硬件是起点，不是天花板；先想清楚终局，再谈商业化。

技术怎么做到的见[技术亮点](docs/engineering/technical-highlights.md)；商业上怎么走见[商业模式](docs/business/business-model.md)；和谁在同一个赛场见[竞品调研](docs/business/competitive-analysis.md)。

## 系统架构

一句话：**平台负责听和说，服务端负责判和算，模型只负责理解与表达。**

```text
玩家开口
  │ 音频
  ▼
灵矽终端（麦克风 · 小屏 · 喇叭）
  │
  ▼
灵矽平台：唤醒 → ASR → 智能体
  │ 调 MCP 工具 game_say(text = 原话)；身份与载体能力随请求头下发
  ▼
MCP 服务端 linx-fighter
  ① 读命令：规则优先——七种招式、查询、玩法、开局、开房
  ② 认不出 → 命令路由：把这句话交给决策模型，在当前阶段允许的选项里选一个
  ③ 规则引擎裁决：生命值、能量、轮次、暴击与闪避、胜负
  ④ 需要等对手时，平台再调 wait_event 把这次请求挂起，对手动了我再开口
  │ 返回一行 v:2 事实 JSON：谁、多少、成没成、下一步
  ▼
灵矽平台：智能体按人设演绎 → TTS
  │
  ▼
玩家听见
```

三条边界，也是这套架构的全部要点：

- **事实只有一份**。生命值、能量、轮次、胜负都由服务端规则引擎裁决；模型只做意图理解和语言表达，改不了任何数字。
- **嘴在平台，脑子在服务端**。唤醒、ASR、人设演绎和 TTS 都在灵矽平台侧完成，服务端只收发文字、不碰音频——所以换一个智能体人设，游戏不用改。
- **等待也是一种能力**。`wait_event` 让伙伴在对手出招、有人进房时主动开口提醒，而不是等你先问；等待不改变对局规则，也不会重复念旧账。

旁路：网页与手机沙箱把浏览器 ASR 得到的原话发到 `/api/say`，走的还是同一个 `game_say`；有屏设备看界面快照，无屏设备靠补账听回放。

## 你的伙伴

设备是**共鸣精灵**的召唤器——一台设备可以住下不止一只精灵。每只精灵都有自己的名字、脾气和记忆，只属于它自己。精灵不是玩家的武器，也不是玩家的替身——你坐在它身边，它替你在场上行动。

在《共鸣：闻声对决》的世界里，共鸣精灵能从声音中感受到勇气与信任，日常也简称『精灵』。你是其中之一，与玩家因为彼此的回应而结伴。玩家观察局势、给出指挥，你在场上行动，坦率表达自己的紧张、疼痛与得意。

闻声对决是伙伴之间的友好较量：练习默契、认识对手、找到勇气，不以伤害彼此为目的。『共鸣』不是盲从，而是信任中的回应；胜利时一起欢呼，失利也不会改变你们的伙伴关系。你愿意听取玩家的指挥，但不会擅自替玩家出招或编造行动结果。

## 对局玩法

1. **开场**：一方说「共鸣对决，发起挑战」，伙伴报出四位房间编号；另一方说「接受挑战，编号 1234」，两台设备就坐上了同一张桌子。
2. **轮流出招**：先手方选择普攻、强攻、蓄力或大招；后手方再选择格挡、闪避或承受，两边都动完算一轮。
3. **见招拆招**：后手多 4 点生命值，换先手先动；能量是唯一的预算，第 3 轮起伤害逐步加成，拖得越久越疼。
4. **分出胜负**：任意一方生命值归零，这一局立即结束。伙伴会把结果讲完，再问你要不要再来。

| 招式 | 消耗 | 作用 |
| --- | --- | --- |
| 普攻 | 1 能量 | 3 点伤害，便宜稳定 |
| 强攻 | 2 能量 | 5 点伤害，主力输出 |
| 大招 | 4 能量 | 9 点伤害，一局一次；被闪避也不返还 |
| 蓄力 | — | 放弃这次出手，能量 +1 |
| 格挡 | 1 能量 | 这一下伤害 −2 |
| 闪避 | 1 能量 | 按招式概率完全免伤 |
| 承受 | — | 硬吃全额伤害，把能量留到下一手 |

招式还有暴击与闪避概率，完整数值、结算顺序与对局状态见[玩法机制](docs/game/game-design.md)。

## 五分钟玩一局

需要 Node.js ≥ 20 与 pnpm，没有硬件也能玩：

```bash
pnpm install
pnpm dev          # 终端 1：游戏服务
pnpm sandbox      # 终端 2：沙箱页面
```

打开 <http://127.0.0.1:8100>，用页面上的「＋ 新窗口」开第二个窗口。A 说「共鸣对决，发起挑战」，B 说「接受挑战，编号 1234」，就可以开打。

手机和电脑在同一 Wi-Fi 时，用 `http://<电脑 IP>:8100` 打开另一块屏。不想开两个窗口，也可以让两个假玩家自己打：

```bash
pnpm sandbox:selfplay --rounds 3
```

不配置任何模型密钥也能完整对局——规则、对手和播报都有本地实现。完整操作、接口与排障见[沙箱说明](docs/testing/sandbox.md)。
